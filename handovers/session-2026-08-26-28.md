5. **`DSN` key missing from live ConfigMap** — The `operan-postgresql` ConfigMap had

   to `sha-aaa2d15`, a `kubectl apply -f modules.yaml` (manifest still pinned to
   `sha-bcce0d9`) reset the deployment. The pod was new (age ~1h) so the "all pods

8. **M03 zombie runs with persistent state** — Enabling `DB_MODE=postgres` made

   (`pending`/`running`/`paused`) as `failed` at startup (commit `b72ca6a`,
   post-rewrite `306c260`; image tag anchored by `deployed-m03-b72ca6a`).

### Deploy verification procedure (mandatory)

After every `kubectl set image` or `kubectl apply`, verify the rollout by reading
the image back from the live deployment. A new pod age is NOT proof of deployment —
`kubectl apply` can silently reset a deployment to the manifest's image tag.

```bash
# For each deployment you rolled:
kubectl -n operan get deploy <name> \
  -o jsonpath='{.spec.template.spec.containers[0].image}'

# Confirm it matches the tag you pushed.
# Then confirm the pod is healthy:
kubectl -n operan get pods -l app.kubernetes.io/name=<name>
```

This step was added after the M05 silent-reset incident (architect P1). The
`kubectl apply` of `modules.yaml` (which still had `sha-bcce0d9`) overwrote the
`kubectl set image` to `sha-aaa2d15`. The pod was new, so age-based checks passed,
but the image was the old one. The architect caught it by reading the image back.
